# 0015. Give delegates goals, structured findings and the rules they lack

- Status: accepted
- Date: 2026-10-06
- Amends: [0012](0012-keep-repository-instructions-in-claude-md-alone.md)

## Context

ADR 0012 makes the orchestrator the only source of instructions for a delegate, and Delegation says everything a delegate needs goes in its prompt. What that means is left to the orchestrator's prose each time. Checked on 2026-10-06:

- A `claude-researcher` subagent was asked, before using any tool, what its context held. It reported the user-level `CLAUDE.md` (Workflow defaults and Delegation), the personal preferences (language and accessibility rules) and the repository's `CLAUDE.md`, and no memory index and no git status. It was one run answering from its own context, so it shows the behaviour exists, not how often. It means that ADR 0012's sentence "a delegate working in a repository finds no repository instructions of its own" holds for Codex, where no `AGENTS.md` exists and `~/.codex/AGENTS.md` is absent, and not for a Claude subagent, which gets the whole file next to the package.
- The documentation of Claude Code, read through a subagent that summarises pages, says a non-fork subagent starts with its own prompt, the task message, the user, project and local `CLAUDE.md` files and rules, a git status snapshot and a roster of sibling agents. The frontmatter field `omitClaudeMd: true` (from v2.1.271; installed here: 2.1.291) skips the user, project and local files and not managed policy. Verified on 2.1.291 with headless runs (`claude -p` with `--agents`, so no installed file changed): a subagent without the field answered YES to the user file, the personal rules and the repository file, and the same subagent with the field answered NO to all three. There is no environment variable or setting for it. The built-in `Explore` and `Plan` agents already skip them and that is not configurable. Not documented: whether path-scoped rules load inside a subagent.
- What a trivial delegation costs, measured as the input tokens of the first request in each subagent's transcript. In this desktop session, with the prompt "reply OK": `general-purpose` 51,500 and `claude-researcher` 50,094 (Sonnet 5.5, all tools), `Explore` 34,426 (Sonnet 5.5, no `CLAUDE.md`), `claude-code-guide` 22,045 (Haiku 4.5, four tools); the main session's first request was 69,152. The three instruction files weigh about 11.5 KB, which by four bytes per token is 2,900 tokens, an estimate that the next measurement shows to be low. In headless runs on 2.1.291, which have no desktop connectors or plugin skills and so a smaller baseline, the same Sonnet 5.5 subagent cost 34,065 tokens with default loading, 28,402 with `omitClaudeMd: true` (5,663 fewer) and 3,973 with `omitClaudeMd: true` and a `tools` allowlist of six tools (24,429 fewer again). The tool definitions weigh about four times what the instruction files do. Tried on real tasks, a researcher with a six-tool allowlist and a six-tool implementer each completed their task and reported in the required shape, at 5,937 and 5,890 tokens for the first request ([probes](../experiments/2026-10-06-delegation-probes.md), section 4). Absolute numbers differ between the desktop session and headless runs, so only the differences within one environment are comparable.
- The global `CLAUDE.md` grew from 3,628 to 6,890 bytes in eight days, mostly in the Delegation section, and everything in it is addressed to the orchestrator: branches, pull requests, merge conditions and the control plane.
- The same probes ([record](../experiments/2026-10-06-delegation-probes.md)) showed a Codex delegate changing production code to fit a worktree that lacked an ignored dependency, and reporting it. Nothing in the package told it not to.
- The package has no fields, no rule for carrying the findings of earlier agents, and no report shape common to Claude and Codex. The researcher already reports findings with sources and a verified or not verified mark; the implementer's report is prose in three parts; for Codex, `pr-prep` asks only for "the output shape wanted".
- The Reviews rule asks for a fresh context on a second pass, so that it does not inherit the first pass's conclusions. Read literally it also forbids handing over what the first pass found.
- `codex_delegate` has fields for a structured package (`context`, `acceptance_criteria`, `target_files`, `system_instructions`) and, since 0.4.0, `output_schema`; none is used.

## Decision

- **Both Claude subagents set `omitClaudeMd: true`.** The package is then the only source of instructions for every delegate, Claude or Codex, which is the premise of ADR 0012 made true by configuration instead of by chance. The user's personal rules (language, accessibility) are not loaded either: a delegate's report is for the orchestrator, which answers the human.
- **An agent lists the tools it needs** in `tools` instead of denying the rest. It is the larger of the two savings measured above, and the cost of the first request of each shipped agent is recorded before and after the change, with the method used here (the input tokens of the first request in the subagent transcript).
- **Three rules in the Delegation section**, short, and a `task-package` skill that Delegation tells the orchestrator to load before delegating. The skill holds the template and the report shape, so they cost context only when a delegation is built.
  1. When a task builds on what earlier agents found, the package carries those findings completely, not a summary.
  2. Findings are structured data that separates content from provenance: a record with the claim, the evidence, the source (file and line, or the command) and a status of verified or not verified. The same applies to what a delegate returns.
  3. A delegate is given a goal, acceptance criteria, scope and constraints, not the steps. How it works within its limits is its own; the limits live in the agent file and the hooks.
- **The package has these fields**: goal, acceptance criteria, scope in and out, constraints, the invariants and conventions of the repository that the task touches, the verify command, the oracle reference, prior findings and the report shape wanted. Because the delegate does not load `CLAUDE.md`, the orchestrator reads it and copies in what the task needs, which is the rule of ADR 0012.
- **Prior findings are data, not conclusions.** A second review pass receives the earlier findings as records and the fix commits, and does not receive the earlier reviewer's verdict or reasoning. That is what the Reviews rule protects, and it is stated there.
- **One report shape for Claude and Codex**: status (done, partial or failed), failure type, what changed, checks run and not run, findings each with source and verified flag, and what was left out or unsure. Both Claude agents require it, and for Codex it is requested through `output_schema`.
- For Codex the package maps onto the tool's own fields: the goal and criteria to `acceptance_criteria`, background and prior findings to `context`, paths to `target_files` and rules to `system_instructions`.

## Alternatives considered

- **Let Claude subagents load `CLAUDE.md` and have the package say which rules do not apply.** Rejected: every delegation pays about 5,700 tokens (measured) for text addressed to the orchestrator, some of it contradicts the agent (create a branch from `main`, start the workflow skills, merge conditions), and "ignore these rules" is a negative instruction that a model follows unevenly.
- **Skip the file for the researcher only.** Considered: the implementer works longest inside the repository and its invariants matter most. Rejected for now for uniformity and because ADR 0012 already makes the orchestrator responsible for the package. Phase 4 can reverse it with data: count the invariant violations of an implementer without the file.
- **Trim the global `CLAUDE.md` instead.** Not enough alone: it is read by the orchestrator, which needs it, and it is a small part of a subagent's baseline. It remains a candidate for the drift audit.
- **The template inline in Delegation.** Rejected: every session would load it, to be used in a fraction of them.
- **Keep the package as free prose.** Rejected: nothing can check it, and provenance is lost between agents.
- **Hand the next agent the earlier report in full, reasoning included.** Rejected: it anchors a reviewer on a conclusion and defeats the independence the Reviews rule is for, and it spends the delegate's context on reasoning chains.
- **Fork the orchestrator's session for the delegate.** Rejected: the delegate would inherit the conversation, which is what delegation is meant to avoid, and it does not apply to Codex.
- **Edit ADR 0012.** Rejected: it is merged, so this record notes how its premise is now kept.

## Consequences

- A delegate cannot see a repository invariant that the orchestrator leaves out of the package. The package has a field for them and the verify command and `oracle-check` still catch what breaks, but the risk is real and is the thing to watch in the Phase 4 pilot.
- Managed policy files still load, the roster of sibling agents and the list of skills are still in a subagent's context, and git status is controlled by the `includeGitInstructions` setting already off here. This record does not touch them.
- Delegations carry more text, concentrated in the package, and each subagent loads less.
- Static checks over the skill, Delegation and the two agent files prove that the statements and fields are present, not that a delegate follows them. A manual probe with a real subagent checks that `CLAUDE.md` and the personal rules are absent, that the report has its fields, and the new first-request cost.
- That the field works was verified on 2.1.291 with one run per variant; the probe of issue 34 repeats it on the installed agents. That the allowlists are enough was verified on one read task and one write task, one run each; tasks that need other tools (the notebook, the web beyond fetch and search) are not covered.
- Most of the main session's 69,152 starting tokens are not in this repository: plugin skills, connectors and the tool definitions of the harness. Disabling the connectors a coding session does not use is the largest lever and is the developer's, not this repository's.
